TASK ID: 8.7
PHASE: 8
TITLE: Fraud/banned email management
STATUS: completed

OBJECTIVE:
Give administrators first-party fraud-blocklist management - ban an email, unban, list - with server-side enforcement at the two boundaries that matter: bid creation (the single choke point before Checkout) and outbid notification sending. No third-party fraud providers, scoring engines, or queues.

ARCHITECTURE:
- migration 20260823000020 creates banned_emails (email_canonical UNIQUE + created_at; RLS enabled with ZERO policies - service-role only)
- Canonical identity = lower(trimmed(raw email)); bids store the trimmed original casing, so enforcement compares case-insensitively against the canonical column
- src/lib/email-bans.ts (server-only): canonicalizeEmail / isEmailBanned / banEmail (ON CONFLICT DO NOTHING upsert -> banned|already_banned by row count) / unbanEmail (exact-count delete -> unbanned|not_banned) / listBannedEmails; admin ops gated through getAdminAuthorization and fail closed

ENFORCEMENT POINTS (both authoritative):
1. createPendingBid (src/lib/bids.ts): after email shape validation, BEFORE category/amount checks - a banned email learns nothing about any category and can never create a pending bid, reach Checkout, or pay. New typed failure reason 'banned_email'.
2. sendOutbidNotification (src/lib/outbid-notification.ts): after the unsubscribe check, BEFORE composition/delivery-attempt gating - banned recipients never receive mail ('recipient_banned'). Unsubscribe consent and fraud bans are separate states checked independently.

ADMIN UI/ENDPOINT:
- POST /api/admin/banned: intents ban | unban | list over form {email}; unauthorized redirects to login; stable ?result=/?error= flags
- GET removed deliberately (no extra JSON dump surface); the page reads server-side via listBannedEmails
- /admin/banned page: ban form + blocklist (canonical emails newest-first) with per-row Unban buttons; result/error banner mapping
- Dashboard management list now links it

PRIVACY:
Only canonical addresses stored/exposed (no IPs/names/device data). The blocklist is distinct from notification_unsubscribes (consent state, HMAC-hashed) - separation preserved per task constraints.
