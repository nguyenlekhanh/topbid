OBJECTIVE:
Provide the client-side subscription infrastructure that streams authoritative public.bids changes to the browser, enabling Tasks 5.2-5.4 to update leaderboard/recent-bid displays without polling or a second state machine.

REQUIREMENT DERIVATION:
PROJECT_PLAN.md specifies "5.1 | Supabase realtime subscription" with dependencies 2.9 (leaderboard query) and 4.8 (conversion). Phase 5 splits display work across 5.2-5.4, so 5.1 is the subscription infrastructure only: listen to authoritative bids changes client-side and expose a typed callback API.

SCOPE:
- New migration supabase/migrations/20260823000014_enable_bids_realtime.sql - adds public.bids to the supabase_realtime publication inside an idempotent guard; without it postgres_changes delivers nothing. RLS preserved: browsers subscribe with the anon key so deliveries are filtered by bids_public_select_paid - clients observe ONLY paid bids, exactly the authoritative leaderboard/recent-bids state produced by the Phase 4 webhook flow.
- New src/lib/realtime.ts - subscribeToBidChanges(onChange): () => void using the existing browser client (supabase.ts createBrowserClient, anon key); channel 'bids-changes' with postgres_changes {event:'*', schema:'public', table:'bids'}; maps payloads to typed BidChangePayload {eventType, new, old}; returns unsubscribe closure calling removeChannel; channel errors logged not thrown.
- RealtimeBidRow declared STRUCTURALLY in realtime.ts rather than importing ./bids: importing would pull server-only modules (service-role Stripe/Supabase paths) into the browser bundle.
