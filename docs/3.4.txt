IMPLEMENTATION NOTES:
Added validateCategory to src/lib/categories.ts after getCategoryBySlug, mirroring Task 3.3's validator conventions (unknown-typed untrusted parameter, runtime guards first, discriminated union with stable string-literal reasons). Flow: reject non-string/blank slugs as 'invalid_slug'; delegate to getCategoryBySlug which normalizes case and filters is_active = true at the app level; null result -> 'category_not_found'; success -> { valid: true, category } carrying the authoritative row (id/slug/name/starting_bid/increment all DB-sourced). Distinguishing missing from inactive would require bypassing RLS or the service-role key - both explicitly forbidden - so both map to 'category_not_found', which is the secure behavior. Combined bid-flow usage is validateCategory(slug) + validateBidAmount(slug, amount); consolidation into one call is left for later tasks if needed.
