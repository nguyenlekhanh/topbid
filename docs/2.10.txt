IMPLEMENTATION NOTES:
Appended after getLeaderboard in src/lib/bids.ts following existing conventions (async createClient, field allowlist BID_FIELDS + LEADERBOARD_CATEGORY_FIELDS). Query mirrors the leaderboard embed pattern: .from('bids').select(`${BID_FIELDS}, categories (id, slug, name)`).eq('status','paid').order('created_at',{ascending:false}).order('amount',{ascending:false}).limit(limit). Rows cast via `as unknown as` because generated DB types are absent (Supabase infers embeds as arrays); mapped via rest destructure ({ categories, ...bid }) so bid contains exactly the Bid fields and category carries the embedded summary. The small limit-guard block is duplicated from getLeaderboard instead of extracted/refactoring the committed 2.9 function, keeping this change purely additive. No rank field on entries (recency feed, unlike LeaderboardEntry).
