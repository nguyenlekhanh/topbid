TASK ID: 8.3
PHASE: 8
TITLE: Category management
STATUS: completed

OBJECTIVE:
Give authorized administrators server-side create/update/activate/deactivate control over categories through the Task 8.1 authorization boundary, with a minimal management UI - no deletion, no 8.4+ scope.

OPERATIONS IMPLEMENTED (exact):
1. CREATE - slug (normalized lowercase kebab, unique), name, description?, starting_bid ($->cents), increment ($->cents), image_url?; is_active defaults true
2. UPDATE DETAILS - name / description / starting_bid / increment / image_url as an explicit patch; slug is IMMUTABLE after creation (public /categories/[slug] URLs are shared assets); empty description clears it; at least one field required; updated_at maintained server-side
3. ACTIVATE / DEACTIVATE - explicit desired state persisted with updated_at; deactivation hides the category from all public surfaces (grid + /categories/[slug] -> 404) while preserving row/bids
NO DELETE: PROJECT_PLAN.md asks only for management of existing category lifecycle; deletion would orphan public URLs and is deferred.

AUTHORIZATION BOUNDARY (unchanged from 8.1):
Every mutation AND the admin list call getAdminAuthorization() first and fail closed ({ok:false,reason:'unauthorized'}) without touching the database. The route re-surfaces unauthorized like any stable error flag.

VALIDATION RULES (server-side; browser input untrusted):
- slug: trim+lowercase, /^[a-z0-9]+(-[a-z0-9]+)*$/, <=80 chars
- name: required non-blank <=120
- description: optional <=500, blank clears
- dollars: optional leading $, ^\d{1,7}(\.\d{1,2})?$, exact rounding to integer cents >=0
- image_url: blank clears to null; otherwise must start http(s):// and be <=2048
- id: strict UUID shape before any query

PERSISTENCE / RLS MECHANISM:
Service-role client inside the server-only module (established share-events pattern) because public RLS grants no write path and management REQUIRES seeing inactive rows that public RLS hides. listAllCategoriesForAdmin() is the isolated privileged read (select * ordered created_at asc); mutations are direct typed inserts/updates with .select('id') so zero-row updates map to 'not_found'. Public RLS policies untouched; public queries (getCategoryBySlug/listCategories) untouched.

DUPLICATE / CONCURRENCY HANDLING:
UNIQUE(slug) remains the final authority for concurrent creates; Postgres 23505 violations (code or legacy message) map to stable 'slug_taken'. Zero-row updates race-safe via PK equality. No invented dedup beyond schema guarantees.
