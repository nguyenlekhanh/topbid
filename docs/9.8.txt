CONCURRENCY GUARANTEES PROVEN:
1. EXACTLY-ONCE DELIVERY GATING: beginDeliveryAttempt returns 'sent' for all callers after the first; only the first proceeds to sendEmail regardless of how many concurrent dispatches occur.
2. SUPPRESSION ORDERING: self_outbid -> recipient_unsubscribed -> recipient_banned -> beginDeliveryAttempt -> compose -> send. Each check short-circuits before later ones AND before any DB write or email send.
3. RATE LIMITER BURST BOUNDARY: allows exactly `limit` requests per identity within a window, blocks overflow with retryAfterSeconds, different identities fully isolated, window expiry re-enables blocked identities.
4. PAYMENT IDEMPOTENCY: processed_webhook_events PK(event.id) + row-locked RPCs ensure exactly-once conversion/refund/failure transitions independent of notification-attempt idempotency.
