PHASE: 7
TITLE: Public category URL
STATUS: completed

OBJECTIVE:
Introduce the project's first public category-specific URL - /categories/[slug] - resolving identity exclusively through the authoritative slug query, with uniform not-found behavior for nonexistent/inactive/malformed slugs.

REQUIREMENT DERIVATION:
PROJECT_PLAN.md specifies "7.4 | Public category URL | 2.7" - dependency on Task 2.7's category queries only. No OG/metadata/tracking/bidding functionality is included (that is 7.5+/other phases).

ROUTE SHAPE DECISION:
/categories/[slug] chosen because the plural prefix was already established in-repo by Hero and CategoryCards hrefs ("/categories"); singular /category/[slug] appears nowhere. Exactly one shape, no aliases.

CATEGORY LOOKUP AUTHORITY:
- getCategoryBySlug (Task 2.7): trim/lowercase normalization of the untrusted URL slug, app-level is_active = true filter + RLS categories_public_select_active; returns null for missing/inactive/malformed alike (no existence leak)
- getHighestBidForCategory (Task 2.8): current top PAID bid, amount DESC, RLS paid-only - no pending bids, no bidder emails, no Stripe identifiers ever rendered
Both existing queries reused verbatim via a small pure loader; zero new SQL, zero schema changes, service role never used for public reads.

NOT-FOUND BEHAVIOR:
loadCategoryPageData returns null -> page calls Next.js notFound() (default 404), matching prompt guidance. Covers: nonexistent slug, inactive/deleted category, malformed/blank input (guarded before any query).

PAGE SCOPE (minimum useful public surface):
Category name, description (nullable), current highest paid bid ("No bids yet" state when none), starting bid, bid increment - all DB-sourced facts already public under RLS. Static metadata title only; NO generateMetadata/OG/Twitter cards (7.5), NO OG image (7.6), NO tracking (7.7). Server component; React escapes all rendered strings (XSS-safe).

SHARING INTEGRATION DECISION (Option A):
Tasks 7.2/7.3 remain UNTOUCHED and continue sharing/copying {APP_URL}/#leaderboard-heading. Updating them to per-category URLs would be an improvement made possible by 7.4, not a correctness requirement of it; per the scope rule that change is deferred to an explicit future task.
