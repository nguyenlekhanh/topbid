TASK ID: 3.3
PHASE: 3
TITLE: Validate bid amount server-side
STATUS: completed

OBJECTIVE:
Validate a proposed (untrusted) bid amount against the server-calculated current minimum valid bid. The minimum is always recomputed from authoritative DB data; client-supplied minimums or category data are never trusted.

SCOPE:
- Extend src/lib/bids.ts (existing bid module; no new files/deps), purely additive to Tasks 3.1/3.2
- New getMinimumBidForCategory(categorySlug): Promise<MinimumBidInfo | null> - unified authoritative minimum resolver composing the two business rules in one query pass
- New validateBidAmount(categorySlug, amount: unknown): Promise<BidAmountValidation> - discriminated-union validation result
- Runtime shape validation of the amount parameter (typeof number, finite, integer, > 0)

OUT OF SCOPE:
- Deeper category validation beyond existence/active lookup (Task 3.4), pending bid record creation (3.5), concurrency/locking (3.6), duplicate transaction prevention (3.7), test infrastructure (3.8), Stripe/checkout/API-route wiring, Zod schema layering (Phase 9 hardening), schema/migration/RLS changes

INPUTS / DEPENDENCIES:
- Tasks 3.1/3.2 rules (starting_bid; highest_paid_bid.amount + category.increment) - now composed in a single resolver
- Task 2.7 getCategoryBySlug, Task 2.8 getHighestBidForCategory (authoritative reads)
- Task 2.4 constraints (amount/increment INTEGER cents >= 0)

IMPLEMENTATION REQUIREMENTS:
- Server-side only via supabase-server anon client chain; respects RLS; no service-role import
- Minimum determined exclusively from DB values; never from client input
- amount typed `unknown` deliberately so runtime guards are enforced regardless of upstream typing
- Validation outcomes: invalid_amount (non-number/non-finite/non-integer/<= 0), category_not_found (missing/inactive category; deeper checks deferred to 3.4), amount_below_minimum (amount < computed minimum, with minimum echoed for UX)
- amount === minimum is valid (it is exactly the required next bid); over-bidding allowed by plan
- Discriminated union return type for exhaustive, type-safe consumer handling
