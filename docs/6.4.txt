OBJECTIVE:
Compose Task 6.1 detection, Task 6.3 template composition, and Task 6.2 delivery into one server-side outbid notification flow, triggered at the authoritative point where a newly paid bid becomes the category's highest bid (verified webhook conversion).

SCOPE:
- New src/lib/outbid-notification.ts: sendOutbidNotification(stripeSessionId) orchestration returning a typed OutbidNotificationResult union ({notified:true, recipient, messageId} | {notified:false, reason}) with reasons new_bid_not_found / no_previous_bidder / self_outbid
- src/lib/stripe-webhook.ts: after processVerifiedEvent returns 'converted' ONLY, deliverOutbidNotification(sessionId) invokes the flow best-effort (logged skip/failure, payment response unaffected)
- src/lib/resend.ts: validation moved from module-load to memoized first-use (identical error messages) - required integration fix; see IMPLEMENTATION NOTES

PRESERVED / BOUNDARIES:
- Recipient/detection sourced authoritatively: getBidByStripeSessionId (Task 4.3, RLS paid-only visibility post-conversion) resolves the new bid {id, category_id, amount, bidder_email, bidder_name} + category name in ONE existing query; getPreviousHighestBidder (Task 6.1) excludes the new bid using established ranking semantics; no client/event-body data trusted
- Delivery exclusively through sendEmail (Task 6.2); no second provider/client created
- Template stays pure (Task 6.3 untouched); no CTA/link (Task 6.5), no unsubscribe (6.6), no retry/failure policy beyond error propagation (6.7); no queues/state/scheduling invented
- Phase 4 idempotency untouched and inherited: the processed_webhook_events event.id PRIMARY KEY makes redelivered events return 'duplicate' BEFORE any conversion, so the notification branch is unreachable for replays - duplicate deliveries can never double-send without any new dedup mechanism
- Self-notification guard: previous top bidder with the same email (case-insensitive) as the bidder who just became highest is never notified ('self_outbid'); first-ever bid notifies nobody ('no_previous_bidder')

IMPLEMENTATION NOTES:
TRIGGER POINT: handleCheckoutSessionCompleted immediately after the ledger RPC commits 'converted'. Alternatives rejected: firing inside DB triggers/RPCs would couple the payment transaction to external HTTP; notifying on already_paid/duplicate would double-send or spam on replays; failing the webhook on email errors could not help since a Stripe retry re-enters the ledger's 'duplicate' branch and never re-attempts conversion or notification - so delivery is best-effort with logged outcomes and retry policy deliberately left to Task 6.7.
BUILD FIX (integration): wiring stripe-webhook.ts -> outbid-notification.ts put resend.ts inside an API route's module graph for the first time; Next.js evaluates route modules during build page-data collection, so resend.ts's module-scope throw broke `npm run build` wherever RESEND_API_KEY is unset (reproduced locally). Validation moved to a memoized ensureConfigured() used by sendEmail - identical messages ('Missing RESEND_API_KEY environment variable', 'Missing RESEND_FROM_EMAIL environment variable'), identical never-silent-failure contract, client constructed once per sender address. This is the only adjustment to a completed-task file beyond additive wiring, documented here honestly.
