CONFIGURATION AUDIT FINDINGS:
1. next.config.ts is intentionally empty (framework defaults only) - no runtime env
   handling beyond Next.js built-ins; nothing to change.
2. .gitignore ignores `.env*` (line: ".env*") AND `.vercel`; `git check-ignore` confirms
   .env.local is ignored. No secrets are tracked anywhere in git history of the repo.
3. .env.example listed all ten variables before this task - but the audit found it was
   NEVER TRACKED BY GIT: the blanket `.env*` ignore rule excluded it, so clones of this
   repository received no environment template at all. Fixed minimally with the standard
   negation convention (`!.env.example` in .gitignore) and committed. The file carries
   explicit SERVER-ONLY/PUBLIC classification comments and a header pointing at this
   document for the operator checklist. NO real values present or added (only empty
   values plus the pre-existing http://localhost:3000 placeholder).
4. Secret-exposure verification (EMPIRICAL, this build): after `npm run build`, a full
   scan of .next/static (all browser chunks) found ZERO occurrences of any server-only
   VALUE (checked Supabase service-role key + Stripe secret key values from local
   .env.local) and ZERO occurrences of any server-only variable NAME. Public vars are
   expected to be inlined by design.
5. Server-only readers are structurally isolated: supabase-service.ts/stripe.ts/
   resend.ts/unsubscribe.ts/stripe-webhook.ts have no 'use client' importers; the only
   browser clients (supabase.ts, stripe-client.ts) read exclusively NEXT_PUBLIC_*
   variables.
6. NEXT_PUBLIC_APP_URL semantics: localhost default for dev; in production it MUST be
   set to the absolute production URL because Checkout success/cancel URLs, share URLs,
   unsubscribe links, canonical metadata, and OG images derive from it.
