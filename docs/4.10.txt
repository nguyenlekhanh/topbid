TASK ID: 4.10
PHASE: 4
TITLE: Payment failure handling
STATUS: completed

OBJECTIVE:
When Stripe authoritatively reports a payment attempt failed (checkout.session.async_payment_failed), transition the linked PENDING bid to the schema-defined 'failed' status - freeing its reservation slot - using the same claim+effect idempotency and DB-boundary patterns as Tasks 4.8/4.9.

REQUIREMENT DERIVATION:
PROJECT_PLAN.md specifies only "4.10 | Payment failure handling | 4.8". The schema already defines the 'failed' status (migration 2.2, CHECK-constrained in 2.4) but nothing could ever set it. The smallest plan-faithful implementation is therefore: handle Stripe's Checkout payment-failure event and mark only the linked pending bid 'failed'. Session-expiry handling was deliberately NOT added (abandonment is not a payment failure; documented as possible follow-up).
