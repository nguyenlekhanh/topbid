KEY FINDINGS BY CATEGORY:

GRANTS/PRIVILEGES: All SECURITY DEFINER mutation functions follow the identical pattern: REVOKE EXECUTE from public, anon, authenticated; GRANT EXECUTE to service_role only. No direct table-level GRANTs exist that could bypass RLS. No ALTER DEFAULT PRIVILEGES statements found.

SEARCH_PATH: Every SECURITY DEFINER function pins search_path = public. All table references inside functions use public.-qualified names. No attacker-controlled schema resolution possible.

SENSITIVE COLUMNS: bidder_email stored in bids (RLS restricts public reads to paid only); stripe_session_id/stripe_payment_intent_id in bids (same RLS restriction); notification_unsubscribes stores HMAC-hashed identities not raw emails; banned_emails stores canonical lowercase emails (admin-only visibility); audit_logs stores actor_user_id + actor_email (admin-only visibility). All protected at DB boundary via RLS, not merely hidden by UI.

CONSTRAINTS/INVARIANTS: bid amount >= 0 CHECK; status CHECK IN ('pending','paid','failed','refunded'); categories starting_bid/increment >= 0; UNIQUE(stripe_session_id); UNIQUE(category_id, stripe_session_id); UNIQUE(slug) on categories; UNIQUE(email_canonical) on banned_emails; event_id PK on processed_webhook_events. All enforced at DB level, not application-only.

TRANSACTIONS/LOCKING: create_pending_bid takes FOR UPDATE on category row (serializes same-category reservations); convert/refund/fail take FOR UPDATE on bid row; ledger insert + state transition in one transaction (rollback on anomaly); duplicate events resolve as 'duplicate' no-op.

CROSS-RECORD AUTHORIZATION: session_mismatch rejection prevents cross-linking sessions to wrong bids; PI-based lookup prevents attaching refunds to unrelated bids; admin_users self-read prevents reading other admins' rows; HMAC token binding prevents unsubscribing another recipient.

SERVICE-ROLE BOUNDARY: supabase-service.ts uses SUPABASE_SERVICE_ROLE_KEY (server-only env var, no NEXT_PUBLIC_ prefix). Verified: no client component imports supabase-service or supabase-server. bids-client.ts uses browser anon client from supabase.ts. Server-only modules never imported by client code.

MIGRATION SAFETY: No accidental privilege widening across migrations. Function replacements preserve grant patterns (revoke/grant re-applied after CREATE OR REPLACE where signature changed). No policies dropped during migrations. Migration 20260823000019 correctly fixed the refund parameter defect without weakening security posture.
