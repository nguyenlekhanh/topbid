TASK ID: 8.1
PHASE: 8
TITLE: Admin authentication
STATUS: completed

OBJECTIVE:
Establish a minimal, reusable server-side authentication/authorization foundation for all Phase 8 admin work - no dashboard, no management UI (Tasks 8.2-8.8 own that).

REQUIREMENT DERIVATION:
PROJECT_PLAN.md specifies "8.1 | Admin authentication | 0.1" - one line. Architecture derived from the repository: @supabase/ssr has been installed since Task 0.5 specifically with cookie-handling server clients, making the platform's native Supabase Auth the established mechanism; no third-party provider was added and no custom session crypto was invented.

CHOSEN ARCHITECTURE:
Supabase Auth email/password + database-backed admin membership.
- WHO IS AN ADMIN: a Supabase Auth user whose id exists in public.admin_users. Session possession alone grants nothing.
- WHAT PROVES IT: valid Supabase Auth session cookie (HttpOnly/Secure/SameSite attributes managed by the installed SDK) AND a readable own-row in admin_users - both verified SERVER-SIDE on every request.
- STORAGE: Supabase Auth session cookies (@supabase/ssr handlers) + admin_users row. No client-visible tokens; service-role key untouched by auth flows.

AUTHORIZATION ENFORCEMENT (fail-closed):
src/lib/admin-auth.ts getAdminAuthorization(): supabase.auth.getUser() -> if no/invalid user => unauthorized (no DB query); then SELECT own row from admin_users under the caller's JWT - RLS policy admin_users_select_own restricts reads to id = auth.uid(), so least privilege holds and the result cannot be widened. Any error (expired session, DB failure) resolves {authorized:false}. This is THE reusable guard Task 8.2+ must call at the top of every protected page/route.

PROTECTED BOUNDARY NOW:
/admin exists as the minimal enforced entry boundary (status card + sign-out only): unauthenticated/unauthorized visitors are redirected to /admin/login server-side BEFORE any content renders (enforcement, not UI hiding). No dashboard/management functionality (Tasks 8.2+).
PUBLIC ROUTES PRESERVED: /, /success, /cancel, /unsubscribe, /categories/[slug], /categories/[slug]/opengraph-image, /api/webhooks/stripe, /api/unsubscribe, /api/share-events - all unchanged and unprotected.

LOGIN FLOW:
- /admin/login: minimal credentials form posting to POST /api/admin/login (progressive enhancement, zero client JS); failures return here with generic ?error=1 - identical response for unknown emails vs wrong passwords (no existence leak)
- POST /api/admin/login: signInWithPassword server-side; honors `next` ONLY after sanitizeNextPath() open-redirect protection (rejects absolute URLs, '//', '/\' protocol-relative tricks) PLUS belt-and-braces resolved-origin equality check so cross-origin redirects are impossible even if sanitization missed an encoding trick
- POST /api/admin/logout: signOut + redirect to login; errors indistinguishable from already-ended sessions
- PROVISIONING: out-of-band SQL/dashboard (create Supabase Auth user, insert id into admin_users). No self-service signup path exists anywhere.

OPEN REDIRECT HARDENING (caught by tests during development):
The initial sanitizer accepted '/\evil.example.com' because it starts with '/' - browsers normalize backslash to slash producing a protocol-relative cross-origin redirect. Fixed by rejecting '/\' prefixes too AND verifying resolved.origin === request.origin before redirecting.
