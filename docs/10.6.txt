TASK ID: 10.6
PHASE: 10
TITLE: Analytics setup
STATUS: completed (repository implementation; LIVE analytics data requires operator activation in Vercel)

OBJECTIVE:
Implement the smallest production-ready analytics consistent with the existing project
and Vercel deployment strategy - best-effort only, completely separated from all
authoritative flows, preserving the privacy/data-minimization model and the existing
first-party share_events telemetry.

EXISTING ANALYTICS/TRACKING AUDIT:
- package.json contained NO analytics provider (no GA/PostHog/Plausible/Fathom/Umami/
  Mixpanel/Segment/Amplitude/Matomo/Vercel references anywhere in src)
- The ONLY first-party telemetry is share_events (Task 7.7): allow-listed x_share |
  copy_link events, event-name-only payload, validating POST /api/share-events with
  per-IP rate limiting, RLS zero policies, strictly non-authoritative
- No cookies for analytics existed; no fingerprinting; no IP/UA collection

PROVIDER DECISION AND RATIONALE:
@vercel/analytics (Vercel Web Analytics) chosen because:
1. Vercel is the established deployment platform (AGENTS.md + plan Deployment Strategy);
   the integration is native and zero-configuration on it
2. Cookieless by design - no consent burden, no new cookies introduced (explicitly not
   required by the task)
3. ZERO environment variables required (unlike GA/PostHog/Plausible which need keys or
   origin allow-lists) - nothing new to classify or leak
4. Smallest possible SDK footprint; script injection is non-blocking by provider design
5. Operator activation is a single dashboard toggle, matching the established Phase 10
   operator-checklist pattern
Alternatives rejected: Google Analytics (heavy SDK, cookies, consent complexity),
PostHog/Plausible/Mixpanel (require keys/endpoints + larger clients), self-built
pageview pipeline (would duplicate share_events infrastructure and add DB writes).

EVENTS / DATA COLLECTED:
- Pageviews ONLY, via the provider's automatic tracking on PUBLIC routes.
- NO custom events are sent. Share/copy actions already have first-party share_events
  telemetry (Task 7.7) which remains untouched and is NOT duplicated.
- Provider-aggregate dimensions only (Vercel dashboard: page counts, referrers,
  countries, device classes). No application code supplies any payload.

DATA EXPLICITLY NOT COLLECTED (by construction):
No email addresses, session ids, Stripe session/payment-intent ids, bid ids,
unsubscribe tokens, admin user ids/emails, raw sensitive URLs (private routes render no
script at all), no custom fingerprinting, no analytics cookies, no IP/UA handling in
application code (provider aggregates are outside app control but the product is
cookieless and privacy-oriented).

IMPLEMENTATION:
- src/lib/analytics-gate.ts (pure): isPublicAnalyticsPath(pathname) - everything is
  public EXCEPT segment-exact matches of /admin, /api, /success, /cancel,
  /unsubscribe (the same private set Task 10.5 excludes from indexing). Segment-exact
  matching means a hypothetical future public route like /administrator-guide can never
  be swallowed. Malformed input fails closed to "not tracked".
- src/components/PublicAnalytics.tsx ('use client'): usePathname() -> gate ->
  renders <Analytics /> or null. Mounted once in src/app/layout.tsx.
- No server-only module touches analytics; no env vars added to .env.example (none
  exist for this provider); no build-time configuration required beyond a normal deploy.

FAILURE BEHAVIOR:
Best-effort by construction: the component renders null or an async script tag - it can
never block page rendering, bidding/payment, Stripe webhooks, authentication,
unsubscribe, notifications, admin operations, or sharing UX. An analytics outage is
invisible to every authoritative flow. Analytics state is never read by any business
logic (presentation-only).

PRIVACY/SECURITY CONSIDERATIONS:
- Private surfaces are structurally untracked (no script rendered there), mirroring and
  complementing the Task 10.5 robots/noindex exclusions
- share_events remains independent first-party telemetry - unchanged and unduplicated
- No real credentials exist anywhere; none were invented

ENVIRONMENT VARIABLES: NONE required by @vercel/analytics (dashboard-toggled product).
RUN_STRIPE_INTEGRATION remains test-only as before.
