TITLE: Update highest bid display
STATUS: completed

OBJECTIVE:
Make the category-card "Current Bid" display update live from authoritative database state when bids change, driven by the Task 5.1 realtime subscription - without trusting realtime payload values or creating a client-side bidding state machine.

REQUIREMENT DERIVATION:
PROJECT_PLAN.md specifies "5.2 | Update highest bid display | 5.1". The existing highest-bid display is the "Current Bid" value in each CategoryCards card (static mock data). 5.2 turns that value live.

SCOPE (three pieces):
- src/lib/bids-client.ts (new) - getHighestPaidBidAmountForCategory(categoryId): Promise<number|null> over the browser anon client (RLS paid-only); lives separately from ./bids to keep server-only service-role modules out of the browser bundle
- src/lib/highest-bid-tracker.ts (new) - createHighestBidTracker(options): () => void; realtime events are SIGNALS only: relevant events (same category_id AND resulting row paid OR DELETE) trigger an authoritative re-fetch via the injected fetcher; bursts coalesce to at most one trailing refetch; callback fires only on actual change; refetch errors logged not thrown; returns unsubscribe
- src/components/HighestBidDisplay.tsx (new, 'use client') - thin wrapper holding the amount state, wiring tracker with real subscribe/fetch, rendering formatted amount (aria-live polite), fallback to initialAmount when authoritative value unknown
- src/components/CategoryCards.tsx - the card's static Current Bid text replaced by <HighestBidDisplay categoryId initialAmount>; mock values remain as initial fallbacks so Phase 1 visuals are preserved until real category ids flow through

PRESERVED / BOUNDARIES:
- Payload rows never trusted for display: every change triggers a fresh authoritative query (RLS-filtered)
- No client-side state machine duplicating pending/paid/refunded logic; no service-role access; no new dependencies
- Tasks 1.1-5.1 logic untouched except the one-line integration point in CategoryCards

OUT OF SCOPE:
- Leaderboard ranking updates (Task 5.3), recent-bid updates (5.4), rank animations (5.5/5.6), reconnection UX (5.7), replacing remaining mock data sources wholesale
