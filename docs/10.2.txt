STATIC VERIFICATION RESULTS (verified from repository/migrations):

A. ORDERING/DEPENDENCIES: filenames sort lexicographically in true dependency order;
   every referenced object is created in an earlier migration. Migration 08 explicitly
   drops the superseded 4-parameter signature before creating the 5-parameter one, so a
   FRESH database ends with exactly ONE create_pending_bid signature (no stale
   overloads). Migration 19 replaces refund_paid_bid in place (same signature).

B. NO LOCAL-ONLY STATE: no migrations reference local files, environment values,
   secrets, or connection strings. Seeds are idempotent (ON CONFLICT DO NOTHING); the
   realtime publication change is guarded (checks pg_publication_tables before ALTER).
   The only external-schema dependency is auth.users (migration 18), which exists on
   every Supabase project by default.

C. TABLES: 10 tables total. All 8 tables queried/written via .from() by application code
   (categories, bids, admin_users, audit_logs, banned_emails, notification_unsubscribes,
   outbid_notification_deliveries, share_events) verified present by scripted grep.
   processed_webhook_events is accessed ONLY inside SECURITY DEFINER functions (by
   design) and exists via migration 11.

D. RPCs: all 5 directly-called RPCs (attach_stripe_session, create_pending_bid,
   fail_pending_bid, process_checkout_completed_event, refund_paid_bid) verified present
   by scripted grep; convert_pending_bid_to_paid exists and is invoked inside the
   process_checkout_completed_event wrapper (never called from app code directly).

E. FUNCTION SECURITY: 8 function definitions across the chain; each pairs
   `security definer` WITH `set search_path = public` and is followed by revokes of
   EXECUTE from public/anon/authenticated and a grant to service_role ONLY - verified
   counts: 8 pinned search_path statements, 8 grant statements, 24 revoke statements.

F. RLS MODEL: 10 `enable row level security` statements = 10/10 tables. Policies:
   exactly 3 exist (categories_public_select_active, bids_public_select_paid,
   admin_users_select_own). SEVEN tables are deliberately ZERO-POLICY (service-role
   only): processed_webhook_events, notification_unsubscribes,
   outbid_notification_deliveries, share_events, banned_emails, audit_logs (+ none
   needed for categories/bids beyond their SELECT policies). Nothing was weakened.

G. INDEXES/CONSTRAINTS: bids indexes (category+status; partial category+amount DESC
   WHERE paid; stripe_session; payment_intent) plus unique-constraint backing indexes;
   audit_logs(created_at DESC); UNIQUEs on slug/stripe_session_id/email_canonical/
   recipient_hash/event_id; CHECK constraints on amounts/status enums/delivery states/
   audit actions/share events - all represented by migrations.

H. NO SECRETS: scripted scan found no secret-like literals (sk_live/sk_test/whsec/sbp
   patterns) anywhere in migrations.
